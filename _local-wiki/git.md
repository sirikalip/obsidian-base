# Git: Полный справочник команд

---

## 1. Просмотр состояния и истории (Status & Log)

```bash
# Текущее состояние (измененные, удаленные, неотслеживаемые файлы)
git status

# Краткий статус (удобно, когда изменено много файлов)
git status -s

# Просмотр изменений построчно (только то, что НЕ добавлено через git add)
git diff

# Просмотр изменений, которые УЖЕ добавлены в индекс (git add)
git diff --staged

# Построчный diff для одного конкретного файла
git diff test.txt

# История коммитов в одну строчку (хэш + сообщение)
git log --oneline

# История последних N коммитов
git log -n 5 --oneline

# История изменений с отображением ветвлений (граф)
git log --oneline --graph --all
```

## 2. Индексация и коммиты (Add & Commit)

### Добавление файлов в индекс (Staging)
```bash
# Добавить вообще ВСЁ измененное, новое и удаленное (из текущей папки и вглубь)
git add .

# Добавить ВСЕ изменения во всем репозитории (независимо от текущей папки)
git add -A

# Добавить только один конкретный файл
git add test.txt

# Добавить несколько файлов по маске (например, только JS-файлы)
git add *.js

# Добавить целую папку со всеми файлами
git add src/

# Добавить только изменения в УЖЕ отслеживаемых файлах (игнорировать новые файлы)
git add -u
```

### Фиксация изменений (Commit)
```bash
# Создать коммит с сообщением
git commit -m "feat: понятное описание изменений"

# Быстрый коммит: автоматически добавить ВСЕ измененные отслеживаемые файлы и закоммитить
# (НЕ сработает для абсолютно новых файлов, их сначала нужно git add)
git commit -am "fix: быстрое исправление"

# Изменить сообщение самого последнего коммита (пока он не запушен)
git commit --amend -m "новое правильное сообщение"
```

## 3. Отмена изменений и откаты (Rollback & Undo)

### Уровень 1: Изменения в коде (файлы еще НЕ в индексе, без git add)
```bash
# Сбросить изменения в одном файле (вернуть к состоянию последнего коммита)
git restore test.txt

# Сбросить ВСЕ изменения во ВСЕХ файлах в текущей директории (Осторожно!)
git restore .

# Сбросить изменения во всех файлах определенного типа
git restore *.txt
```

### Уровень 2: Файлы уже добавлены в индекс через `git add` (Unstaging)
```bash
# Убрать один файл из индекса (файл останется измененным, но не пойдет в коммит)
git restore --staged test.txt

# Убрать ВСЕ файлы из индекса
git restore --staged .
```

### Уровень 3: Изменения уже закоммичены (Работа с историей)
```bash
# [БЕЗОПАСНО / ДЛЯ СЕРВЕРА] Отменить самый последний коммит (создает анти-коммит)
git revert HEAD --no-edit

# Отменить конкретный коммит по его хэшу
git revert <хэш_коммита> --no-edit

# [ТОЛЬКО ЛОКАЛЬНО] Удалить последний коммит, но ОСТАВИТЬ код в файлах (код станет unstaged)
git reset --soft HEAD~1

# [ТОЛЬКО ЛОКАЛЬНО / ОПАСНО] Полностью уничтожить последний коммит и ВСЕ изменения в файлах
git reset --hard HEAD~1
```

> [!WARNING] Важно при откатах
> Команды с `--hard` стирают код безвозвратно. Если код уже отправлен в GitHub (`git push`), для отмены всегда используй только `git revert`.

## 3.1. Временное сохранение (Stash)
Используется, если нужно переключить ветку или сделать `git pull`, но текущую работу коммитить еще рано.

```bash
# Спрятать все незакоммиченные изменения во временный карман
git stash

# Спрятать, включая новые (неотслеживаемые) файлы
git stash -u

# Посмотреть список спрятанного
git stash list

# Достать последние спрятанные изменения обратно в файлы и удалить их из "кармана"
git stash pop

# Очистить "карман" без применения изменений
git stash clear
```


## 4. Ветвление и переключение (Branches)

```bash
# Посмотреть список локальных веток (текущая отмечена звездочкой *)
git branch

# Посмотреть локальные + удаленные (remote) ветки
git branch -a

# Создать новую ветку и сразу переключиться на нее
git switch -c feature-name
# (Старый аналог: git checkout -b feature-name)

# Переключиться на существующую ветку
git switch main
# (Старый аналог: git checkout main)

# Удалить ветку (только если ее изменения уже влиты в main)
git branch -d feature-name

# Принудительно удалить ветку (даже с незамердженными изменениями)
git branch -D feature-name
```

## 5. Слияние веток (Merge)

> [!TIP] Правило мерджа
> Всегда переходи в ту ветку, **КУДА** ты хочешь влить код, перед вызовом `merge`.

```bash
# 1. Переходим в целевую ветку (обычно main)
git switch main

# 2. Вливаем ветку с фичей в текущую
git merge feature-name

# Прервать слияние, если возник сложный конфликт (вернуть всё назад)
git merge --abort
```

## 6. Клонирование (Clone)

```bash
# Клонировать репозиторий (создаст папку с именем репозитория)
git clone git@github.com:USER/REPO.git

# Клонировать с кастомным именем для создаваемой папки
git clone git@github.com:USER/REPO.git my-folder-name

# Клонировать файлы НАПРЯМУЮ в текущую папку (папка должна быть ПУСТОЙ)
git clone git@github.com:USER/REPO.git .
```

## 7. Отправка и получение изменений (Remote / Push / Pull)

```bash
# Отправить текущую ветку на GitHub (первый раз, привязывает ветку к origin)
git push -u origin feature-name

# Отправить изменения (если ветка уже привязана)
git push

# Скачать актуальные изменения из текущей ветки с GitHub в локальный код
git pull

# Скачать изменения со всех веток с GitHub, но не вливать их сразу в файлы
git fetch
```

### Что делать, если push отклонен? (Non-fast-forward error)
Если кто-то успел отправить изменения раньше тебя, GitHub отклонит твой `git push`.

```bash
# 1. Скачиваем изменения с GitHub и аккуратно ставим свои коммиты ПОВЕРХ них:
git pull --rebase

# 2. Если конфликтов нет, просто отправляем:
git push
```
